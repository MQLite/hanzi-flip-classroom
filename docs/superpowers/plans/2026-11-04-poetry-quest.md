# 古诗书房闯关实现计划

**Goal:** 在原课堂网站加入可独立游玩的古诗解谜闯关页面。

**Spec:** `docs/superpowers/specs/2026-11-04-poetry-quest.md`

**Architecture:** 独立HTML入口；纯状态模块负责依赖、判定和存储校验；DOM界面与原创SVG书房负责交互。首页仅增加链接，Vite构建同时输出两页。

**Tech Stack:** 原项目Vite、原生JavaScript、SVG、Vitest、Playwright。

## 约束与检查重点

- 不改原题库及其存储键；仅增加独立游戏存储。
- 两条分支可先后探索；提交受前置线索约束。
- 重复通关、重复投递不能重复收集或多次结算。
- 挑战模式需要文字证据；提示不扣分、不代替正常判定。
- 无效存储重置到可用起点，禁用存储仍可完成本次游戏。
- 手机无全页横向溢出；按钮有名称并可用键盘操作。

## 任务

1. 写状态与持久化行为测试并观察缺少模块时失败；实现 `createQuest`、`inspectObject`、`solvePuzzle`、`deliverLetter`、`requestHint`、`restoreQuest`、`getProgress`。验证所有分支及数据边界。
2. 先写完整通关、重载/重置、首页入口和手机交互测试；实现 `quest.html`、状态驱动视图、SVG场景与CSS。观察未实现页面的测试失败，再运行通过。
3. 集成首页入口与多页面构建；更新使用说明。运行全量单元测试、相关浏览器用例和构建，检查桌面与手机截图。
4. 审查变更，必要修正后发布到指定仓库，等待GitHub Pages部署成功并核对线上入口。

## 本地验证记录

- 123项单元测试通过，含7项解谜状态、前置关系、证据与存档校验测试。
- 8项新游戏浏览器测试通过，覆盖完整通关、错误投递、存档、重置、手机、键盘及受限存储。
- 原有四模式进度与1280×720布局的2项浏览器回归测试通过。
- 独立审查发现的三项问题均已先以失败用例复现，再修正为通过：未完成分支时查看已得信件、零解题但已有探索时的替换确认、小屏滚动及焦点维护。
- 使用GitHub Pages项目基础路径的生产构建通过。新增页面不引入运行依赖。
