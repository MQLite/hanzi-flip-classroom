# Maze 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline, task by task.

**Goal:** Add a3D maze explorer that walks only after confirmed reading and celebrates after reaching the exit.
**Architecture:** Pure world/motion/framing helpers, persistent Three.js scene and projected native buttons, unchanged maze core and lesson flow.
**Tech Stack:** Existing Three.js/JS/CSS/Vitest/Playwright; no new dependencies.
**Spec:** docs/superpowers/specs/2026-11-08-maze-3d-design.md.

## Global Constraints
- Same9×9 grid, lesson characters, adjacent read gate, mode snapshots and bank schema.
- A confirmed move animates one legal step; selecting/refreshing never moves the avatar.
- Exit celebration follows walking and plays once; input waits during movement/reward, explicit exits remain available.
- Persistent canvas/shared GPU resources; no idle/inactive frame loop.
- Hidden/inactive/reset/context loss/reduced-motion changes settle and unlock; flat fallback remains interactive.

## Review Focus
- Pending read choices and repeated/fast inputs must never move twice or skip a wall.
- Final walk must complete before celebration, with no replays on text refresh or mode return.
- A round reset or delayed scene callback cannot alter a new round or leave controls locked.
- Projected labels must stay aligned, legible, in frame and clickable across aspect ratios.
- Context loss, display switches and visibility changes must preserve authoritative core position and same-lesson continuation.
