# 句子小火车：统一三维车站与烟花

## 用户目标与执行范围

用户要求“使全场景3d化，画面更优美，成功组词开出有烟花效果”。本次针对刚上线的句子小火车，理解为拼句成功（包括老师接受）后发车并绽放烟花。沿用本任务此前的 Route 自动实现授权及提交部署到同一网站的明确指令，自动完成设计、实现、审查、验证与更新；不修改其他游戏的玩法。

这是现有游戏舞台的场景重构。目标是让车站、候选车厢和答题火车真正属于同一个可见的三维空间，并让成功反馈更有观赏性，同时保持课堂投屏清晰、操作简单。

## 美术与空间方案

采用明亮的微缩童话车站：柔和天空背景、具有侧面厚度的草地地形、少量山丘、树木与花丛、带屋顶和站牌的小站房、月台、围栏、铁路及出站隧道。所有游戏场景物体用 Three.js 实体网格构建。暖色阳光、环境光、材质色差和柔和投影体现物体厚度；圆润的火车、轮毂、连杆和连接件比现有方盒更精致。

一套 renderer / scene / camera 渲染整个舞台。候车区位于前景，答题轨道穿过中景，站房和自然景物形成后景；消除当前上下两块画布的视觉割裂。固定略俯视三分之四视角，不自动旋转相机。文字牌面朝向观众，保持词语从左到右阅读。教师设置、计分、参考句和操作按钮使用清晰 HTML，围绕舞台布局。

候选车厢有稳定停车位，选择时从停车位平滑驶入答题轨道末尾，取消时返回原位；其他车厢按顺序平滑收拢。保持语义按钮和模型的准确投影对应，按钮投影在每次节点重建、窗口变化和动画完成后更新。普通选择动画期间应保持视觉位置与可点击目标同步或短暂锁定相应移动目标，避免点到错误车厢。

## 成功发车与烟花

自动匹配或教师判对都触发同一种成功演出：车轮转动、烟囱冒出轻柔蒸汽，火车朝左侧出站方向驶去；车站上空依次出现至少两束可辨认的烟花，先上升再向外绽放，并带短尾迹和淡出。演出约 2–2.5 秒结束后进入下一题。

烟花使用处于场景坐标中的粒子、发光点和短轨迹，不用页面角落的表情图标代替。色彩以金色、珊瑚色和青蓝色为主，在词语区域上方或后方绽放，不遮挡尚需阅读的词语。不新增音效，不持续自动播放烟花；错误、揭晓和跳过不触发成功庆祝。

核心记分及结算保持既有一次性规则。场景动画 Promise 取消、切换模式、重开、页面隐藏或 WebGL 丢失时必须安全完成或取消视觉演出，由现有 token 机制保证只推进一次。所有临时粒子、蒸汽和 RAF 清理干净，旧回调不能在下一轮触发。

## 保留的课堂能力

保留 36 课、72 条句子、3–7 节词语车厢、手动切分、撤回、清空、教师判对、再练与回顾，以及三种游戏的独立状态。无需改动题库结构或纯状态规则。

1920×1080 和 1280×720 均须同时看到所有候选词、已接车厢、主要按钮和反馈，六字词语保持清晰比例；最长七节题也要验证。窄屏保持整页无横向溢出，可对统一舞台进行局部横向滚动并自动显示新接车厢，候车区与按钮仍可触达。允许移动端纵向滚动。

保留键盘焦点连续性、可读状态反馈、编辑时快捷键隔离。无 WebGL 或手动简化时，继续使用完整可玩的 HTML 车厢。减少动态效果偏好下不播放烟花、蒸汽和长距离位移，直接完成结算；不得因视觉降级丢失得分或输入。

## 代码与性能边界

主要修改 `sentence-train-scene.js`、`sentence-train.js`、`sentence-train.css`。场景较复杂时拆出 `sentence-train-models.js` 与 `sentence-train-effects.js`，各自负责模型和暂态效果，外部场景 API 保持不变。必要时适配原有浏览器测试的旧布局假设，但保留原本保护的操作、滚动、投影、回调和状态要求。

复用几何体、材质及文字纹理，单场景阴影贴图上限 1024、像素比上限 1.75。限制烟花与蒸汽的粒子数量和生命期，静止时按需绘制；页面隐藏和场景未激活时不继续动画。销毁时释放 renderer、监听器、观察器与资源。避免通过新增重型依赖或持续后处理来堆砌效果。

## 验收

1. 单一 WebGL 画布中的完整三维车站一眼可辨，包含统一的停车区、铁轨、月台、站房、立体地形、植被和出站结构；车体有清晰顶面、侧面、圆形车轮及真实投影。
2. 点击候选词语准确接到火车，取消返回原位置；真实坐标点击、重开同题、复习、缩放和模式切换均保持目标对齐。
3. 拼句成功和教师判对均有可见发车、蒸汽、上升并绽放的烟花；失败和跳过不播放。保存演出中途的实际截图，并查看烟花爆发帧，不只验证类名或数据属性。
4. 演出前后的得分、进度及取消行为通过针对性回归。减少动态效果、无 WebGL、上下文丢失和页面隐藏均能完整继续课堂。
5. 查看 1920×1080、1280×720、390×844 下真实截图，含最长词语、七节车厢和成功动画。补充有必要的边界断言，执行完整单元、浏览器回归和生产构建。
6. 独立视觉审查和代码审查通过后，合并推送既有 main，确认 GitHub Pages 部署成功，并在线验证新版舞台和成功演出。
