# 句子小火车设计

## 设计状态与教学目标

2026-09-20，用户选择“词语排队”，并确认以下方向：点击词语车厢排列句子、参考答案自动检查、教师接受其他合理语序、Three.js 实体火车、沿用《汉语乐园》1A–3B 课次与小组计分，作为汉字奇遇岛的第三种游戏。

本文将已确认方向细化为可实施的设计，供用户审阅；书面设计通过后再编写实施计划。本文尚不表示功能已实现或发布。

面向小学汉语课堂，由老师操作投屏、学生口头参与。成功标准是：老师能够按教材选题，让学生排列词语，检查并讲解答案，计分、回顾和复习；切换其他游戏后可继续原有课堂进度。

## 范围与方案

采用“点击接车厢 + 本地参考答案 + 教师补充判断”。点击便于投屏操作和触屏使用；拖拽可作为后续增强，本期不作为完成游戏的必要操作。使用显式、经过核对的词语切分，不依赖运行时自动分词或联网语言模型判分。

本期包含：三维车站和火车、词语排序、撤回与清空、检查答案、教师判对、参考答案、计分、回顾、复习、教材筛选、题库中的切分编辑与备份兼容。沿用现有前端和本地存储，不增加账号、后端、倒计时、语音识别或自由输入造句。

## 完整课堂流程

1. 点击“句子小火车”。首次进入时沿用当前筛选和组名，建立独立轮次；之后进入恢复该模式原有状态。
2. 每轮最多八道不同句子。候选题先按来源、阶段和范围筛选，再检查切分有效性，按完整参考句去重后抽取。不按目标汉字去重；同一句在多道汉字题中出现，本轮只出现一次。
3. 主画面显示“把词语排成一句话”，不提前显示完整参考句。候车区展示打乱的全部词语车厢，轨道上保留火车头和句尾标点位置。本期不增加干扰词，所有车厢都必须使用。
4. 点击候车区车厢，追加到轨道排列末尾；点击已接上的车厢，将其放回候车区，其余车厢依次收拢。“撤回”放回最后一节，“清空”放回全部车厢。候车区位置稳定，放回不会重新洗牌。
5. 每题使用 3–7 节词语或自然短语车厢，每节 1–6 个汉字，全句正文不超过 28 个汉字。相同词语可出现多节，各车厢使用独立 ID，每节恰好使用一次。标点固定在句尾，不占词语车厢。
6. 车厢未全部接上时，“发车”不可提交，并显示还差几节。排齐后点“发车”，按词语序列检查本题有效参考答案。
7. 命中参考答案，立即给提交时选定的小组加一颗星，锁定本题结果，播放约 1.2 秒火车出发动画，随后自动进入下一题。最后一题驶出后进入总结。
8. 未命中参考答案，显示“与参考答案不同，可以调整，也可以请老师判断”。车厢保持当前排列，不扣分、不自动判为再练。车厢可短暂轻晃，避免散落打乱学生思路。
9. 未命中且完整排列时出现“老师判对”按钮。老师认为语序合理即可接受，使用相同的一次计分与发车流程，记录实际提交句子及教师判定来源。排列发生变化后该按钮收起，须重新检查当前排列。教师接受不自动修改题库答案。
10. 次级按钮“看看参考句”揭晓本题的标准句。揭晓后仍可调整排列练习；自动检查只报告匹配情况，每次完整排列检查后，无论是否匹配，都提供“老师判对”按钮，计分须由老师点击，避免照抄后直接自动奖励。排列改变后按钮收起，重新检查后再显示。揭晓前后均可标记“再练一次”，锁定本题且不计分，再由老师进入下一题。
11. “下一句”跳过未结算题，记为未作答；“上一句”回顾保存的排列、参考句及结算结果，不能重复得分或改写已结算记录。沿用现有已跳过题不再计分的规则。
12. 总结展示各组星星、已完成句子、教师接受的句子、再练与未作答数量。复习只取明确标记再练的原题快照，清除本次排列、重新打乱并重新计分；不把跳过的句子自动判错。

## 题库内容与课次覆盖

首版逐课整理《汉语乐园》1A–3B 全部 36 课，每课至少两道有明确切分的句子，即至少 72 条课次关联记录。优先选用现有配编例句，保证每册至少八个不同的可用参考句；同一句允许用于不同课次，但一轮内去重。

内容按自然词语和短语切分，例如“老师 / 在 / 看书”，保留“老师”“苹果”等完整词语。所有内置切分在交付前逐句核对词义、语序、标点和长度。所选例句是教学配编，不宣称来自课本原句，也不宣称所有搭配字均已在本课学过。

已有新版《中文乐园》和个人题库筛选仍可使用：具有有效手动切分或匹配内置切分的例句可参与。首版不承诺这些来源的逐课覆盖；界面显示实际可用题数，零题时引导在题库管理中补充切分。

内置切分作为独立内容表，记录来源题目 ID、对应完整例句、词语数组、句尾标点和可选的其他参考顺序。只在当前题的 ID 及规范化后的完整例句同时匹配时应用。不得用相近例句或单个目标字推测切分。

老师修改例句后，原内置映射自然失效；显示“此例句尚未设置有效车厢切分”，不影响该题在识字和组词游戏中的使用。不自动覆盖老师原有例句，不要求已有用户恢复默认题库。

## 可编辑数据与持久化

在既有题目结构中增加可选的 `sentenceTrain` 对象，沿用 `schemaVersion: 1` 和现有存储键；旧备份无此字段仍可导入。对象结构为：

```json
{
  "tokens": ["老师", "在", "看书"],
  "punctuation": "。",
  "alternatives": []
}
```

`tokens` 为标准顺序；`alternatives` 为其他可接受的词语数组列表，最多五条。每条替代顺序须与标准词语具有完全相同的词语及出现次数，不得增加、丢失或拆分词语；重复答案去重。`punctuation` 仅接受一个中文句号、问号或感叹号。首版不收录含句中标点的排序题。

标准词语直接连接再加标点，必须等于原题规范化后的 `sentence`。规范化仅进行 Unicode NFC 与去除首尾空白，不改写原句或自动去掉句中标点。词语长度、数量、字符范围和全句长度按课堂流程中的限制校验。

题库管理增加“句子小火车”折叠区，显示有效内置切分或老师保存的切分。老师用 `/` 分隔车厢，替代答案每行一条，实时预览；帮助明确 `/` 仅是编辑分隔符。提供启用手动切分和清除手动切分操作。没有手动字段时尝试匹配内置表；不强制每道汉字题都有火车题。

启用后的无效切分使当前编辑草稿不能保存，并给出具体错误；老师可修正或清除手动切分。旧题无此字段不属于错误。批量导入中若提供了该字段但结构无效，整体拒绝且保留原题库。导出携带有效手动字段；内置映射随应用提供，无需写入所有用户题库。

存储失败、未保存草稿、导入预览和恢复默认继续使用现有机制。编辑器必须往返保留新增字段，禁止切换题目或修改无关字段时静默丢弃。题库文本始终按文本绘制和展示，不作为 HTML 或代码执行。

## 视觉与交互

使用固定斜俯视镜头的小车站：浅绿色地面、站台、铁轨、枕木、火车头和彩色词语车厢。车头具有驾驶室、烟囱和车轮，车厢具有厚度、连接件及车轮。文字印在朝向镜头的车厢牌面上，与真实模型同步移动。

教学阅读顺序始终从左到右。左侧车头作为排列起点，各词语向右连接；发车时整体向左驶离。车站不是纯装饰，候选车厢、接车厢和发车均由同一状态驱动。完成的句子进入旁边的“旅程记录”，以清晰文字展示，不再堆积额外三维火车。

点击接车厢或放回时播放短距离移动，约 200–300 毫秒；检查成功后整列出发。检查失败仅轻晃或显示文字反馈，不播放撞车、脱轨等动画。没有持续旋转镜头或循环烟雾，不增加默认音效。

主界面提供“撤回”“清空”“发车”，揭晓参考句、教师判对和再练为次级操作。小组面板沿用现有位置。火车模式隐藏当前单字拼音开关，不用已有目标字拼音拼凑整句读音；其他两种游戏的拼音偏好保留。

投屏优先保证词语和按钮可读，检查 1920×1080 与 1280×720。390×844 窄屏中让课堂面板上下排列，词语车厢候选区换行；轨道允许在明确的局部容器内横向滚动，自动展示新加入的车厢，不造成整页横向溢出。

## 状态、计分与动画边界

火车模式独立保存筛选、组名、选中小组、题目快照、当前题、打乱顺序、逐题排列、揭晓记录和结算记录。题目及嵌套词语数组深复制，题库编辑和教材补充只作用于下一轮。

三种游戏切换时保存和恢复各自状态。首次进入火车模式不复制另一游戏的得分或答题记录。修改筛选、开始新一轮或更改组名只重置当前模式，已有进度时沿用确认提示。课堂进度仅在本页会话保存，刷新后重置；题库长期保存在本浏览器。

计分由结算记录派生。自动匹配与教师接受都通过同一结算入口，一题最多一颗星，冻结实际句子、判定来源和获分小组。连续点击、动画回调、回看、切换模式和重复触发均不能额外计分。

成功提交进入出发状态后冻结排列、判分和前后导航；允许切换模式或重开。切换模式时直接完成当前发车和一次前进，再保存快照；重开则取消旧回调，初始化新轮次。出发完成使用轮次标识和题目 ID 校验，旧回调不能推进新题或新轮次。

## 实现结构与集成边界

- `src/sentence-train-content.js`：人工核对的内置例句切分与替代答案，包含教材来源关联。
- `src/sentence-train-data.js`：字段校验、内置映射解析、筛选、按句去重和快照构造。规则独立于 DOM、Three.js 与存储。
- `src/sentence-train-core.js`：轮次、车厢 ID、洗牌、排列、提交、教师接受、导航和复习的纯状态函数。
- `src/sentence-train.js`：可访问的界面与语义操作，接收状态并发出操作意图。
- `src/sentence-train-scene.js`：Three.js 模型、投影、点击命中、动画、激活、简化及资源清理，只负责显示。
- `src/sentence-train.css`：车站与响应式样式，选择器限定在火车模式范围。
- `src/main.js`：第三模式入口、独立快照、共用教师工具、模式相关文案及场景生命周期协调。
- `src/storage.js`、`src/editor.js`：可选字段校验、编辑与导入导出，不改变原有核心字段的要求。

现有 `core.js` 按汉字去重，且要求揭晓后才能判分，不适合直接冒充句子轮次。火车模式采用自己的纯状态模块，遵循相同的分组、结算、导航和复习语义；通过清晰的当前模式分派接入公共界面。仅对共享入口做必要整理，不重构识字或组词规则。

开始实现前检查其他开发中的变更。本次探索中观察到主目录有并行进行的场景和界面工作，因此实现阶段应重新确认最新基线并使用独立工作区。集成时保留其他工作的功能，不覆盖或提交无关改动。本设计阶段只新增本文。

## 降级、性能与可访问性

车厢提供可聚焦的语义按钮，与三维命中事件调用相同操作；三维模式的辅助按钮不得挡住模型文字或形成重复视觉标签。按钮名称包含词语及当前位置，重复词语能被区分。键盘可完成选词、撤回、清空和提交，减少重绘导致的焦点丢失。

空格在具体按钮上使用原生行为；页面空白处可提交当前排列，方向键执行课堂导航。表单输入、下拉选择、中文输入法组合、打开任何对话框期间停用课堂快捷键。反馈通过文字及 live region 提供，不只依赖颜色和动画。

WebGL 初始化失败、上下文丢失或手动简化后，使用 HTML/CSS 车厢提供同样的排序、检查、教师接受和回顾。切换显示方式不重新洗牌、不改变分数。遵循系统减少动态效果设置，缩短或取消动画但完成相同的一次状态转移。

仅激活当前模式场景。页面隐藏时暂停绘制，恢复后安全完成尚未结束的出发流程；静止时按需渲染，限制像素比和阴影开销，复用几何体与材质。销毁时清理 RAF、计时器、监听器、观察器、纹理和渲染器，反复切换不累积画布。

零题显示筛选条件、无可用题的原因及题库管理入口，不开始空轮次。不足八题显示实际数量。洗牌避免初始序列恰好等于任一参考答案；若所有可区分排列均为有效答案，则允许显示原序并提示可直接检查，避免无限重试。

## 验收与验证

### 内容与纯规则

- 校验 36 课各至少两条关联记录、各册至少八个不同可用句；全部内置切分可还原对应例句，替代顺序词语计数一致。
- 重复词语使用独立车厢；每节只能使用一次，撤回、放回和清空保留稳定候车位置；初始洗牌不会无限循环。
- 不完整排列不能提交；命中、未命中、教师接受、揭晓后练习、再练和跳过分别遵循上述结算规则。
- 重复提交、动画中切换、重开及延迟回调不能重复计分或跳题；轮次快照的嵌套数组与题库隔离。
- 按句去重而不是按汉字去重；教材筛选、空题、不足八题、复习及回顾结果正确。
- 无新增字段的旧备份兼容；字段编辑与导入导出往返保留；无效字段拒绝保存，旧映射在例句变更后失效。

### 浏览器与视觉

- 完整跑通选择课次、接车厢、调序、错误重试、自动发车、教师判对、揭晓后判分、再练、总结与复习。
- 三个模式各自操作后往返切换，检查筛选、组名、分数、题号与草稿独立恢复；其他工作新增的场景交互保持可用。
- 检查真实三维模型、车厢牌面文字、车头方向与文字阅读顺序、接车厢和出发动画。
- 在三种目标尺寸检查可读性、按钮可达性、局部轨道滚动及整页无溢出；用键盘完成一题。
- 验证减少动态效果、手动简化、WebGL 不可用、上下文丢失、页面隐藏及多次模式切换。
- 实现后执行相关 Vitest 测试、Playwright 流程和现有回归，再运行 `npm test`、`npm run test:ui` 与 `npm run build`，按实际结果报告。
