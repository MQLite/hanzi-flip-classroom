# 组词小工坊设计

## 需求与设计状态

用户希望在汉字奇遇岛中完成“组词小工坊”，利用 Three.js 添加 3D 模型。2026-09-20 已确认课堂组词、教师判分、题库复用和模式切换方向，并明确本期不制作特定词语对应的模型。用户随后通过本文，并授权依据 Route 规则自主完成计划、实现、验证和独立审查，不重复请求阶段批准。

面向现有小学汉语课堂：教师操作投屏，学生口头参与。成功标准是老师能独立完成选题、拼词、揭晓、判分、复习，并能在两种游戏之间往返而不丢失各自进度。3D 使用通用工坊模型服务这一过程。

## 范围与方案选择

采用“点击拼字 + 通用 3D 工坊”。纯口头组词的操作少，但缺少拼搭过程；自由拖拽三维物件的操作精度要求高，不适合常见课堂投屏。本期采用点击添加字块，不要求拖拽或旋转视角。

包含木质工作台、字块、传送带、盖章器和收集架。不制作动物、植物、建筑等与具体词语对应的模型，不新增模型下载服务。保留现有前端技术栈和本地题库，课堂运行不依赖外部 CDN。

## 课堂流程

1. 页面提供“识字翻翻乐”和“组词小工坊”两个模式按钮，当前模式有明显的文字与选中状态。
2. 工坊沿用教材阶段、整个阶段／本课／累计范围、个人题库与年级筛选。每轮最多八个不同目标汉字；不足八字时按实际数量开始。
3. 出题区显示目标汉字及可关闭的已有单字拼音。提示“用这个字，组一个词”。字块区提供由本题参考词拆出的汉字，打乱展示；同一字块可重复点击，以支持“爸爸”等词。
4. 每次点击把一个字追加到拼词槽。提供“撤回一字”“清空”和“输入其他词语”。输入其他词语直接替换当前拼词，不改变参考答案和题库。
5. 拼词采用 2–8 个汉字，必须包含目标字。输入前后空格自动去除；其他空格、标点或非汉字给出具体提示，不静默改写答案。使用 Unicode 字符计数，不能把一个扩展汉字当成两个字。未满足格式要求仍可揭晓参考词和标记再练，但不能记为答对。
6. 教师点击“揭晓参考词”。展示题库中的两个参考词和原有例句，并标明“其他合理组词也可以，由老师判断”。不自动判断词义正误，不把例句描述为学生所拼词语的例句。
7. 教师先选作答小组，再点击“答对了”或“再练一次”。答对加一颗星；再练不扣分。揭晓后、结算前仍可修改拼词，方便记录学生补充的答案。结算后冻结该题拼词和结果。
8. “下一字”继续；直接跳过时记为未作答，不自动判错。回看能看到原拼词和判定，不能重复计分。
9. 一轮结束显示各组得分、成功组词、待巩固及未作答数量。“开始复习”只纳入明确标记再练的题，沿用题目快照并重新计分，不把跳过的字自动算错。

首轮采用现有默认筛选。无需账号、自动语音识别、倒计时或联网词典。

## 题库使用与教学边界

直接使用既有题目的 character、pinyin、words 和 sentence，教材归属与来源说明保持原义。题库编辑、导入导出继续使用现有 schemaVersion 1，不为工坊复制另一份题库。

参考词是提示，不是完整正确答案集合。题库中的词语可能包含目标字以外的未学汉字，界面提示“搭配字可能超出本课，可由老师带读”。不声称所有搭配字都属于当前教材课次。

字块区仅从符合本期拼词格式且包含目标字的参考词中拆字、去重，然后随机排列；保证目标字可选。可用字块超过十二个时，只提供目标字和前十二个不同搭配字，其余词可通过输入完成。若没有可用参考词，提示“请老师输入组词”，仍保留题目和原始参考内容，不悄悄删除教师题库。

只显示题库已有的目标字拼音，不由单字拼音拼凑整词读音，不对多音字猜测语境。题库文本通过文本节点渲染，不能作为 HTML 执行。

## 通用 3D 模型与视觉

沿用暖白、木色、浅绿及金黄色的课堂风格。固定略俯视的镜头：中央是木质工作台与拼词槽，前方为短传送带，一侧为盖章器，后方为收集架。汉字、提示和操作采用清晰的 HTML 文字层，与模型位置协调，避免透视损害识读。

模型使用 Three.js 几何体、圆角方块、材质和光照在本地构建。字块有厚度和柔和阴影；桌腿、传送带滚轴、收集架隔板形成可辨认的工坊，而不只展示装饰方块。字块数量反映当前拼词长度，架上成品数量反映本轮答对题数，架旁以 HTML 列出真实收集词语。

点击字块时，通用字块滑入拼词槽；撤回时移除最后一块；答对后盖章器下压，拼词成品沿短传送带移到架上，伴随短暂星星奖励。动画最长约一秒，判分立即写入状态，不等动画结束才生效；切题或切换模式可直接结束动画并显示最新状态。

不持续自动旋转镜头。像素比上限 1.7，阴影贴图上限 1024，复用几何体与材质。页面不可见或模式未激活时停止渲染。减少动态效果偏好下不播放位移、盖章和粒子动画，直接显示最终状态。

“简化显示”保留相同 HTML 字块、拼词槽、收集词语和全部答题操作。WebGL 初始化失败或上下文丢失时自动降级，状态、得分和当前输入不变。恢复立体显示仅尝试恢复渲染，不重新开局。

## 两种模式与状态边界

两个模式分别保存本轮题目快照、当前题索引、揭晓状态、判定记录、选中小组、组名、筛选条件和拼音开关。组词模式另保存逐题拼词草稿和字块顺序。切换模式时保存并恢复对应状态；首次进入工坊时以当前课堂筛选和组名初始化独立轮次。

切换模式本身不弹出清空进度确认。开始新一轮、改变筛选或应用组名时，使用现有确认机制，仅重置当前模式；另一模式保留原轮次和组名。题库全局共享，修改从各模式下一轮生效，不能改动已经开始的题目快照。

题库长期保存在浏览器；两种游戏的课堂进度仍只保存在内存，刷新会重置。帮助中明确这一点，不新增进度持久化或账户同步。

## 代码组织与接口

- `src/main.js`：继续管理题库、全局对话框、课堂工具及游戏模式入口。将当前模式相关状态集中管理，避免两套快捷键同时响应。
- `src/core.js`：复用选题、揭晓、判分、前后导航、得分与复习规则。新的拼词状态与原有识字会话分开，不把 Three.js 引入核心规则。
- `src/workshop-core.js`：纯函数生成可选字块、验证拼词、维护逐题草稿和已结算词语；同轮回看时保留字块顺序和输入。计算仅消费题目快照与会话状态，不读写 DOM 或浏览器存储。
- `src/workshop.js`：组词视图及事件绑定。接收当前题目、草稿、揭晓与判定状态、收集词语，发出添加、撤回、输入和揭晓意图。通过文本节点显示所有题库内容。
- `src/workshop-scene.js`：构建通用模型；提供更新拼词长度与收集数量、播放奖励、设置简化显示、激活／暂停和销毁的方法。只负责显示，不判分。
- `src/scene.js`：为现有翻牌场景补齐激活／暂停及资源清理，使模式切换时只有当前场景绘制。
- `src/styles.css` 与可独立引入的工坊样式：模式入口、字块、拼词槽、输入区、收集列表及响应式布局。

分数和收集架均从已结算记录派生，不能依赖奖励动画累加。销毁场景时清理 RAF、ResizeObserver、事件监听器、几何体、材质和渲染器。不能因反复切换模式累积画布和监听器。

## 可访问性与异常

字块为真实按钮，可用键盘聚焦并激活。输入框、撤回、清空、模式切换都有明确名称。键盘 Space 在聚焦具体按钮时执行按钮默认操作；无具体控件焦点时揭晓当前游戏。左右键切题；输入框、选择框、可编辑内容或打开对话框时，课堂快捷键暂停，中文输入法组合期间也暂停。

参考答案、格式错误、得分及降级提示同时提供文字反馈，不只依靠颜色或动画。输入时不重建整个表单，避免丢失焦点和中文输入法组合内容。

无题时显示空态及题库管理入口，不初始化无意义的轮次。窄屏时上下排列舞台、操作和分组；16:9 投屏优先保证目标字、拼词、主按钮可见。模型不得覆盖字块按钮或挡住文本。

## 验收与测试

### 规则测试

- 重复字拼词“爸爸”、目标字在词尾、不同 Unicode 汉字、非汉字输入、少于二字、超过八字、缺少目标字均有明确结果。
- 未揭晓不能判分；格式无效不能记为答对；其他合理组词不因未命中参考答案而被系统判错。
- 已结算题重复操作和回看不重复计分；跳过题为未作答；复习只包含标记再练的题。
- 草稿和字块顺序在切题、回看及模式切换后保留；题库修改不改变已开始的轮次。
- 无可用参考词、过多搭配字、空题库和少量题库都有可继续的明确界面。

### 浏览器与视觉验证

- 完整跑通点击拼词、撤回、清空、中文输入、揭晓、选组、答对、再练、总结、复习。
- 两种模式分别作答后切换，检查筛选、组名、得分、输入及进度独立恢复。
- 检查输入法组合、按钮聚焦和对话框期间快捷键隔离；验证题库文本按文字显示。
- 分别检查 1920×1080、1280×720 和 390×844；确认无横向溢出、汉字不裁切、主操作可达。
- 实际检查 Three.js 画布中的工作台、字块、传送带、盖章器和收集架，以及添加和奖励动画。验证减少动态效果、手动简化、WebGL 不可用与上下文丢失。
- 反复切换模式检查只有一个活跃渲染循环，关闭及重建不累积画布和监听器。
- 执行 `npm test`、`npm run test:ui`、`npm run build`；保留现有识字、题库编辑、教材筛选及笔顺测试通过。
